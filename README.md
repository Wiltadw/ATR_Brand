# ATR Brand — فروشگاه آنلاین عطر

> **وضعیت فعلی: پایان فاز ۲ (دیتابیس و بک‌اند).**
> سرور، دیتابیس، APIها، امنیت و محاسبه قیمت آماده و تست‌شده‌اند.
> **ظاهر سایت** (فاز ۳) و **صفحات پنل مدیریت** (فاز ۴) هنوز ساخته نشده‌اند؛ پس فعلاً در مرورگر فقط خروجی اطلاعات (JSON) را می‌بینید، نه صفحه‌ی زیبای فروشگاه.

---

## ۱. اجرا روی کامپیوتر خودتان (ویندوز)

### پیش‌نیاز: Node.js
در PowerShell یا Command Prompt بزنید:

```
node -v
```

باید عدد **20.6 یا بالاتر** ببینید (ترجیحاً ۲۲). اگر خطا گرفتید یا عدد کمتر بود، نسخه‌ی LTS را از سایت nodejs.org نصب کنید.

### مراحل (فقط بار اول)
۱. پوشه‌ی پروژه را از حالت زیپ خارج کنید، داخل آن PowerShell باز کنید و بزنید:

```
npm install
npm run init-env
npm run setup
npm run sample:add
```

| دستور | کاری که می‌کند |
|---|---|
| `npm install` | بسته‌های لازم را نصب می‌کند (چند دقیقه طول می‌کشد) |
| `npm run init-env` | فایل `.env` را با کلیدهای تصادفی می‌سازد و **رمز مدیر را نمایش می‌دهد؛ همان لحظه یادداشتش کنید** |
| `npm run setup` | دیتابیس را می‌سازد و مدیر و تگ‌های پیش‌فرض را اضافه می‌کند |
| `npm run sample:add` | ۸ محصول **آزمایشی** (با برچسب «نمونه آزمایشی»)، اطلاعات تماس و هزینه ارسال آزمایشی اضافه می‌کند |

### هر بار که می‌خواهید سرور را روشن کنید
```
npm run dev
```
سپس در مرورگر باز کنید: <http://localhost:3000/api/products>

برای خاموش کردن: `Ctrl + C`.

## ۲. چطور تست کنم؟

**تست خودکار (پیشنهادی):** سرور را با `npm run dev` روشن بگذارید، یک PowerShell **دوم** باز کنید و بزنید:

```
npm run test:api
npm run test:currency
```

باید پایان هر دو این باشد: `… ناموفق: 0` (۹۷ بررسی برای `test:api` و ۲۰ بررسی برای `test:currency`).

> ⚠️ `test:api` برای تست، یک سفارش آزمایشی و یک محصول موقت می‌سازد (محصول موقت را خودش پاک می‌کند). اگر بعد از آن دوباره اجرایش کنید، بخش‌هایی که تعداد دقیق را می‌شمارند ممکن است ناموفق شوند. برای تکرار تمیز: سرور را ببندید، پوشه‌ی `data` را پاک کنید و `npm run setup` و `npm run sample:add` را دوباره بزنید.

**تست دستی در مرورگر** (فقط خواندنی‌ها):

| آدرس | چه می‌بینید |
|---|---|
| `/api/products` | لیست محصولات با قیمت درهم و تومان |
| `/api/products?q=رز` | جستجوی فارسی |
| `/api/products?q=Oud` | جستجوی انگلیسی |
| `/api/products?tags=گرم,شبانه` | فیلتر چندتگی |
| `/api/products?gender=WOMEN&sort=price_asc` | فیلتر جنسیت + ارزان‌ترین |
| `/api/products/citrus-lumiere-sample` | صفحه یک محصول + مشابه‌ها + تاریخچه قیمت |
| `/api/tags` | همه تگ‌ها |
| `/api/store` | اطلاعات فروشگاه، نرخ فعلی و هزینه ارسال |

**حذف محصولات آزمایشی** (وقتی محصولات واقعی را اضافه کردید): `npm run sample:remove`

## لوگو

لوگوی «برند» (نستعلیق، صورتی نئونی، داخل مربع) آماده است و داخل پوشه‌ی `public/brand` قرار دارد:

| فایل | کاربرد |
|---|---|
| `logo.svg` | لوگوی اصلی با درخشش نئونی (برداری، بدون افت کیفیت) |
| `logo-flat.svg` | نسخه‌ی ساده برای آیکون‌های کوچک (همین الان آیکون تب مرورگر است) |
| `logo-word.svg` | فقط کلمه، بدون مربع، شفاف؛ برای نوار بالای سایت |
| `logo-1024.png`، `logo-512.png`، `logo-192.png` | نسخه‌های تصویری |

حروف به «مسیر» تبدیل شده‌اند، پس برای نمایش لوگو به نصب هیچ فونتی نیاز نیست. فونت اصلی Noto Nastaliq Urdu است (مجوز آزاد OFL).

## تست روی گوشی (وقتی ظاهر سایت ساخته شد)

گوشی و کامپیوتر باید به **یک وای‌فای** وصل باشند.

۱. به‌جای `npm run dev` این را بزنید: `npm run dev:phone`
۲. در PowerShell بزنید `ipconfig` و عدد جلوی **IPv4 Address** را بخوانید (مثلاً `192.168.1.20`).
۳. روی گوشی در مرورگر بنویسید: `http://192.168.1.20:3000` (عدد خودتان را بگذارید).
۴. اگر ویندوز پرسید «Allow access»، روی **Allow** بزنید (فقط برای شبکه‌ی خصوصی).

اگر باز نشد: مطمئن شوید گوشی از داده‌ی همراه استفاده نمی‌کند و روی وای‌فای مهمان (Guest) نیست.

## ۳. چه چیزهایی ساخته شد؟

- **دیتابیس:** مدیر، محصول، تصویر، تگ، دسته، نرخ ارز و تاریخچه‌اش، سفارش، اقلام سفارش، تاریخچه قیمت، تنظیمات فروشگاه، و جدول `payments` (برای درگاه پرداخت در آینده).
- **قیمت:** قیمت اصلی همیشه به **درهم** ذخیره می‌شود. تومان هیچ‌وقت ذخیره نمی‌شود و هر بار از «درهم × نرخ فعلی» حساب می‌شود، پس با عوض شدن نرخ، همه قیمت‌ها خودکار درست می‌شوند.
- **نرخ ارز:** نرخ دستی از همان ابتدا کار می‌کند و **همیشه اولویت دارد**. بروزرسانی خودکار هم آماده است (هر شب ۳ بامداد تهران) ولی چون هنوز منبع نرخ تعیین نکرده‌اید، فعلاً خاموش/بدون منبع است. اگر منبع خطا بدهد، نرخ قبلی حفظ می‌شود، خطا ثبت می‌شود و مدیر آن را می‌بیند. نرخ صفر، منفی یا جهش بیش از ۳۰٪ نسبت به نرخ قبل پذیرفته نمی‌شود.
- **محصول و تصویر:** افزودن، ویرایش، حذف، آپلود و تعویض تصویر. تصویرها بررسی، کوچک و به WebP تبدیل می‌شوند و نام تصادفی می‌گیرند.
- **تگ و فیلتر:** تگ‌های پویا (ساخت/ویرایش/حذف)، فیلتر چندتگی، جنسیت، بازه قیمت، مرتب‌سازی، جستجوی فارسی و انگلیسی.
- **سبد و سفارش:** قیمت سبد **در سرور** حساب می‌شود (قیمتی که مرورگر بفرستد نادیده گرفته می‌شود). محصول «ناموجود» یا «به‌زودی» قابل ثبت نیست. هزینه ارسال جدا نمایش داده می‌شود. پاسخ ثبت سفارش صریحاً می‌گوید «ثبت درخواست به معنی پرداخت نیست».
- **مشابه‌ها، تاریخچه قیمت، موجودی:** مشابه‌ها بر اساس تگ، خانواده بویایی، جنسیت و قیمت؛ تاریخچه‌ی قیمت فقط داده‌ی واقعی ثبت‌شده را نشان می‌دهد و علت تغییر (تغییر نرخ ارز / تغییر دستی قیمت درهمی / تخفیف) را جدا نگه می‌دارد.
- **امنیت:** رمز با هش argon2، کوکی نشست امن (HttpOnly)، بررسی منشأ درخواست (CSRF)، اعتبارسنجی همه ورودی‌ها، محدودیت تعداد تلاش (ورود، سفارش، …)، دسترسی مدیر در سرور بررسی می‌شود، هدرهای امنیتی، خروج، نشست را در سرور هم باطل می‌کند.

## ۴. تصمیم‌های فنی (به زبان ساده)

| تصمیم | چرا |
|---|---|
| **Next.js + TypeScript** | هم سایت و هم بک‌اند در یک پروژه‌اند؛ فقط یک چیز را اجرا و منتشر می‌کنید. |
| **SQLite (یک فایل)** برای شروع | بدون نصب چیز اضافه؛ برای یک فروشگاه کوچک تا متوسط کاملاً کافی است. |
| **Drizzle به‌جای Prisma** ⚠️ | در فاز ۱ گفتم Prisma. موقع ساخت، دانلود موتور Prisma در محیط کاری من مسدود بود، پس همان نقش را با Drizzle انجام دادم. برای شما فرقی ندارد، ولی **این تغییر نسبت به پیشنهاد اول است.** |
| **ذخیره درهم به «فلس»** | یعنی ۲۵۰ درهم = ۲۵۰۰۰ فلس؛ تا خطای اعشاری در محاسبات پول پیش نیاید. |

## ۵. محدودیت‌ها و نکات صادقانه

- **رفتن به PostgreSQL:** در فاز ۱ گفتم «بدون بازنویسی کد». با Drizzle دقیقاً اینطور نیست: تعریف جدول‌ها باید برای PostgreSQL بازنویسی شود (کار متوسط، نه صفر). **راه ساده‌تر:** با همین SQLite روی یک سرور مجازی (VPS) با دیسک پایدار منتشر کنیم، یا از دیتابیس ابری سازگار (Turso) استفاده کنیم که فقط با عوض کردن `DATABASE_URL` و `DATABASE_AUTH_TOKEN` کار می‌کند. در فاز ۸ دقیق مقایسه می‌کنم.
- **نرخ ۲۵٬۰۰۰ تومان آزمایشی است و واقعی نیست.** قبل از هر نمایش واقعی، نرخ درست را وارد کنید (در فاز ۴ از پنل؛ تا آن موقع از طریق API).
- **«پرفروش‌ترین»** فعلاً با علامت‌گذاری دستی توسط مدیر مشخص می‌شود، چون هنوز فروش واقعی ثبت نشده.
- **محدودیت تعداد درخواست** در حافظه‌ی سرور است؛ برای یک سرور کافی است.
- **بروزرسانی خودکار نرخ** تا وقتی منبع نرخ تنظیم نشود هیچ کاری نمی‌کند (و وانمود به موفقیت هم نمی‌کند).
- **اعلان ایمیلی سفارش** فعلاً نیست (فقط پنل)؛ طبق گفته‌ی شما بعداً اضافه می‌شود.
- هنوز **روی هاست واقعی منتشر نشده** و ادعایی هم درباره‌ی آنلاین بودن نمی‌کنم.

## ۶. تصمیم‌هایی که از شما لازم دارم

۱. **منبع نرخ خودکار:** فعلاً دستی. هر وقت خواستید (مثلاً کلید API از Navasan یا سرویس مشابه)، همان را در `.env` وصل می‌کنیم.
۲. **نرخ واقعی درهم** و **هزینه‌ی ارسال واقعی** (فعلاً آزمایشی: ۱۵۰٬۰۰۰ تومان).
۳. **اطلاعات واقعی تماس برند** (فعلاً آزمایشی؛ تا فاز ۴ لازم نیست).
۴. **لوگو:** دارید یا یک لوگوی متنی ساده برای ATR طراحی کنم؟ (برای فاز ۳)

## ۷. پشتیبان‌گیری (خلاصه؛ نسخه کامل در فاز ۸)

همه‌ی اطلاعات فروشگاه در دو جا هستند: پوشه‌ی **`data`** (دیتابیس) و **`storage`** (تصویرها). از این دو پوشه گاهی یک کپی روی فلش یا فضای ابری بگیرید.

## ساختار پروژه

```
app/api/…      APIهای عمومی و مدیریت
app/uploads/   ارائه امن تصویرها
db/            تعریف جدول‌ها و اتصال دیتابیس
drizzle/       فایل‌های ساخت دیتابیس
lib/           منطق اصلی (قیمت، ارز، سفارش، امنیت، آپلود)
scripts/       ساخت دیتابیس، داده نمونه، تست‌ها
instrumentation.ts   زمان‌بند ۲۴ ساعته نرخ
```
